# Textbook Tutor Skill

Index a textbook PDF into Docling chunks, a deterministic chapter/section map, hierarchical summaries, and a LanceDB hybrid index, then answer questions with page citations. ToC parsing is delegated to one subagent. Summaries are generated by a standalone Python script that calls any OpenAI-compatible chat-completions endpoint.

## When to Use

- The user supplies a textbook PDF and asks about its chapters, sections, pages, figures, or concepts.
- The user wants a reusable index so later questions do not re-parse the book.
- The user asks for section-level explanations, comparisons, or citations back to page ranges.

Don't use for generic PDF editing, form filling, OCR cleanup, or non-textbook documents — use the `pdf` skill instead.

## Prerequisites

- Linux with Python 3.11+ in a virtual environment: `terminal(command="python -m venv $SKILL_DIR/.venv && source $SKILL_DIR/.venv/bin/activate")`
- Install dependencies once:
  `terminal(command="python -m pip install -r \"$SKILL_DIR/requirements.txt\"")`
- Configure the summary endpoint once:
  1. Copy `$SKILL_DIR/scripts/settings-example.py` to `$SKILL_DIR/scripts/settings.py`.
  2. Set `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_TIMEOUT_SECONDS`, `OPENAI_MAX_RETRIES`, and `OPENAI_TEMPERATURE`.
  `settings.py` is gitignored and never committed.
- First run downloads the Docling layout models and `Qwen/Qwen3-Embedding-0.6B`. Allow network and disk time.

## How to Run

Set `SKILL_DIR` to the directory containing this `SKILL.md`, then invoke every script with `terminal`:

```text
terminal(command="python \"$SKILL_DIR/scripts/preprocess.py\" \"/abs/path/book.pdf\"")
```

Run from the directory that should hold generated data. Every generated artifact — chunks, ToCs, pictures, LanceDB data, locks, and logs — is stored under the current working directory. There is no environment variable override.

## Quick Reference

| Stage | Command | Output |
|---|---|---|
| 1. Preprocess | `python "$SKILL_DIR/scripts/preprocess.py" <pdf>` | `chunks/`, `toc_raw/`, `pictures/` |
| 2. Parse ToC | delegate subagent, write JSON | `toc_parsed/<pdf>.json` |
| 3. Postprocess | `python "$SKILL_DIR/scripts/postprocess_toc.py" <pdf name>` | `toc_enriched/<pdf>.json` |
| 4a. Index | `python "$SKILL_DIR/scripts/db_populate.py" <pdf name> [--force]` | `lancedb_data/` |
| 4b. Summarize | `mkdir -p logs && nohup python "$SKILL_DIR/scripts/summary_generator.py" "<pdf name>" >> "logs/<pdf name>.log" 2>&1 &` | summaries in `toc_enriched`, `logs/`, lock |
| 5. Query | `python "$SKILL_DIR/scripts/db_skills.py" <pdf name> --chapsum` | citations and text |

`<pdf name>` is the PDF file name without `.pdf`. Add `--force` to stage 4b to regenerate existing summaries.

## Procedure

1. **Preprocess the PDF.** Run `preprocess.py` with the absolute path. If it reports no ToC pages, rerun with `--toc-pages 3-5` (1-indexed, accepts `3-10` or `3,4,5`). Use `--force` to rebuild chunks, pictures, raw ToC, and metadata. Completion: `chunks/<pdf>.jsonl`, `chunks/<pdf>.meta.json`, `toc_raw/<pdf>.txt`, and `pictures/<pdf>/` exist, and the command printed `Raw chunks and ToC contents successfully saved`.

2. **Parse the ToC with a subagent.** Read `references/toc-schema.md`. Delegate `toc_raw/<pdf>.txt` with the exact system prompt and `TOCStructure` schema from that file. Write the returned JSON to `toc_parsed/<pdf>.json` with the `write_file` tool, preserving numeric strings for chapter/section keys. Completion: the file validates against `TOCStructure` and contains every chapter and section from the raw ToC.

3. **Postprocess the ToC.** Run `postprocess_toc.py <pdf name>`. Completion: `toc_enriched/<pdf>.json` exists and every chapter/section has `start` and `end` page numbers. This command refuses to run while summary generation is active.

4. **Index and summarize.**
   - Read `references/summary-generation.md` for the endpoint settings, lock protocol, log format, and rerun behavior.
   - Run `db_populate.py <pdf name>`. It prints JSON with `pdf_name`, `table_name`, `row_count`, and `reused`. Completion: `lancedb_data/<table_name>.lance/` exists and the command reported a row count without error.
   - Confirm `$SKILL_DIR/scripts/settings.py` exists and is configured. If it does not, stop and ask the user to copy and fill in `$SKILL_DIR/scripts/settings-example.py`. Do not invent endpoint values.
   - Launch the generator detached, from the data root:
     `terminal(command="mkdir -p logs && nohup python \"$SKILL_DIR/scripts/summary_generator.py\" \"<pdf name>\" >> \"logs/<pdf name>.log\" 2>&1 &")`
   - **Do not wait, poll, sleep, or keep the response open.** Immediately tell the user that summary generation is running in the background, name `logs/<pdf name>.log` as the progress log, and explain that queries fail until `toc_enriched/.<pdf name>.lock` disappears. Then end the response.
   - Completion, checked on a later turn: the lock file is gone, `logs/<pdf name>.log` ends with `Finished summary generation`, and `toc_enriched` has a non-empty summary for every chapter and section (fallbacks cover empty content). `toc_parsed` stays exactly as the ToC subagent wrote it.
   - If `db_skills.py` raises `Summary generation is already running`, generation is still active. Do not retry in a loop and do not delete the lock manually. Tell the user it is still running and show the last lines with `tail -n 20 "logs/<pdf name>.log"`.
   - If `db_skills.py` raises `Summary generation is incomplete`, relaunch the stage 4b command in the background. Existing non-empty summaries are skipped.

5. **Answer the question.** Read `references/query-workflow.md` and follow the three-step retrieval loop:
   - `db_skills.py <pdf name> --chapsum` — pick at most 3 relevant chapters.
   - `db_skills.py <pdf name> --secsum 1,2` — pick at most 3 relevant sections.
   - `db_skills.py <pdf name> --secraw 1.1,2.3` — read the raw text.

   Answer only from retrieved text, cite `<chapter name> (pp. <start>-<end>)`, and use `vision_analyze` on `pictures/<pdf>/pic_<id>.png` only when a figure is essential.

## Pitfalls

- **No ToC detected**: Docling may find no `document_index` items. `--toc-pages` is the escape hatch; do not guess chapters from headings.
- **Page-label offsets**: PDFs with roman front matter map printed labels to physical pages. Keep `chunks/<pdf>.meta.json`; postprocessing needs its `page_labels`, `page_count`, and `toc_offset`.
- **Legacy page ranges**: the last chapter ends at `page_count - 1`, and a section's `end` equals the next section's `start`. These are intentional parity choices.
- **Table reuse**: `db_populate.py` reuses an existing LanceDB table unless `--force` is given. A stale table keeps old metadata; rebuild after changing chunks or the ToC.
- **Raw parsed ToC**: `toc_parsed` is the unmodified ToC subagent output and is never rewritten. Summaries go only into `toc_enriched`, which has normalized section IDs and computed `end` pages.
- **Summary lock**: `summary_generator.py` owns `toc_enriched/.<pdf>.lock` while it runs. `postprocess_toc.py`, `db_populate.py`, and every `db_skills.py` option refuse to run while that lock is active. A lock whose process is dead, reused, or not running `summary_generator.py` for that PDF is removed automatically with a warning.
- **Detached generation**: never run the generator in the foreground, wait for it, or poll its log. The lock and log are the only status surfaces. There is no status subcommand.
- **Summary failures**: an API error or empty model response leaves that summary empty, logs the traceback, continues to the next task, and makes the process exit `1`. Rerun the same background command to retry; completed summaries are skipped.
- **Empty summaries**: `--chapsum` and `--secsum` raise `RuntimeError` naming the missing chapters/sections and the exact rerun command. `--secraw` and `--picid` still work while summaries are missing.
- **No-content tasks**: sections without chunks get `No content available for Section <c>.<s>`; empty chapters get `No content available for <name>`. These fallbacks are non-empty, so use `--force` to replace them after chunks are added.
- **Force regeneration**: add `--force` to the generator to replace every existing summary for that PDF. The default skips any non-empty summary.
- **Settings**: `scripts/settings.py` is manual and gitignored. Never commit API keys or hardcode endpoint values in scripts.
- **Picture payloads**: `--picid` returns base64 in the legacy shape. Prefer `vision_analyze` on the picture file for normal question answering.
- **1-indexed pages**: every CLI page number is physical and 1-indexed, matching Docling provenance.
- **Duplicate PDF names**: data is keyed by the PDF stem. Two books with the same stem collide; use separate working directories or rename one file.
- **Current directory only**: run every stage from the same data root. Generated data is never discovered from the skill directory.

## Verification

- `chunks/<pdf>.meta.json` exists and its `page_labels` length equals `page_count`.
- `toc_parsed/<pdf>.json` validates against `TOCStructure` and is unchanged from the subagent output; `toc_enriched/<pdf>.json` validates against `EnrichedToc`.
- `lancedb_data/<table_name>.lance/` exists, and `db_populate.py` reported a table plus FTS index without error. `<table_name>` is the PDF stem with characters outside `[A-Za-z0-9_.-]` replaced by `_`.
- `toc_enriched/.<pdf name>.lock` is absent, and `logs/<pdf name>.log` exists and ends with `Finished summary generation`.
- Every enriched chapter/section has a summary (fallback text is acceptable only for empty content). `db_skills.py --chapsum` and `--secsum 1` succeed without a `RuntimeError`.
- Spot-check `--secraw 1.1` and `--picid 1`.
- Compare a few page ranges with the legacy `chapters_sections.json`; they must match exactly.
